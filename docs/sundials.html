C++ Code Generation for Solving with SUNDIALS

NOTE: Code generation is currently limited to systems with 0 or 1 kinematic constraint equations (instances of CDS_Component_Constraint). The exported equations mirror the equations used by solveMode "solveTime2".

The software can export the system equations (the ODE) to C++, in a format ready for solving with the SUNDIALS CVODE solver.

General workflow:

  1. MATLAB: Define the system description as usual, and then export the system equations instead of solving them.
  2. CMake/C++: Edit CMakeList.txt to include the exported equations.
  3. CMake/C++: Build the CMake project, and execute the compiled file to solve the equations.
  4. MATLAB: Import the solution from the text file, and continue as if it were the output of calling solve.

Setup / Install

Follow the installation instructions for your operating system

  • lib_ubuntu/instructions/Install_Instructions_Ubuntu.txt
  • lib_windows/instructions/Install_Instructions_Windows.txt

Step 1: Code Generation

In MATLAB, define the system description as usual, continuing up to when you would usually call CDS_Solver.Solve. Then, set the export path in the solver options and call .Solve with the solveMode "sundials". This will generate the equations and export them to C++ instead of solving them.

The generated code is required to be placed in a subdirectory of data/sundials_generated/. Use CDS_GetDataLocations to help form this directory path.

% Given:
%   The generated code is desired to be created in "data/sundials_generated/myModels/myPendulum/"
%       where the subdirectory depth and names "myModels/myPendulum/" may be changed as desired
%   SO = CDS_Solver_Options
%   sys = CDS_SystemDescription

exportPath = CDS_GetDataLocations().sun_generated("myModels", "myPendulum");
SO.exportPath = exportPath;

S = CDS_Solver(SO);
S.Solve(sys, "sundials");

As a result of this, the following files will be created:

  • data/sundials_generated/myModels/myPendulum/crane_head_shared.cpp
  • data/sundials_generated/myModels/myPendulum/crane_head.cpp
  • data/sundials_generated/myModels/myPendulum/crane_inputs.cpp
  • data/sundials_generated/myModels/myPendulum/crane_ode.cpp
  • data/sundials_generated/myModels/myPendulum/crane_x.cpp

These files collectively define the ODE. If you open these files, you will see that the variable names have been minified. The comments next to the variables display the names that you specified while building the system description.

Step 2: Configure CMake

Edit run_sundials/src/SimC3/CMakeLists.txt, setting the variable SunGenerated_Includes to the path to the directory holding the generated code. Specify this path as relative to data/sundials_generated/. List the paths to all the models that you wish to solve.


# CMake
set(SunGenerated_Includes
    "myModels/myPendulum"
    "myModels/myDoublePendulum"
    "myModels/myLinkage"
)

Step 3: Build and execute the C++

Build and execute the CMake project with your preferred CMake and C++ tooling.

When running the executable, the SUNDIALS and OpenBLAS shared library files must either be on the system path, or copies of them must be placed in the same directory as the built executable. Specifically, sundials_cvode.dll and libopenblas.dll. The provided helper scripts automatically modify the system path for you (the modification is temporary and local to the lifetime of the current PowerShell session).

The built executable prints the results to standard out in csv format, with solver statistics appended. These results should be echoed into a text file, ready for importing back into MATLAB. Any filename and path is fine, but the nominal path is in a subdirectory of data/sundials_results/, using the same name as the executable file. For example:


# BASH or PowerShell
#   Run commands from the root CDS directory

# To run without using the helper scripts
# Given:
#   The required dll files are on the system path, or otherwise in "run_sundials/bin/"
#   The generated executable is "run_sundials/bin/myModels-myPendulum.exe"
#   The results are desired to be created in "data/sundials_results/myResults/myModels-myPendulum.txt"
#       where the subdirectory and file names "myResults/myModels-myPendulum.txt" may be changed as desired
& "./run_sundials/bin/myModels-myPendulum.exe" > "./data/sundials_results/myResults/myModels-myPendulum.txt"

In the results, the first column is the solution time. The remaining columns are the state derivative followed by the state. The csv header row uses the variable names that you specified while building the system description. Example results:

Specific instructions for various operating systems and build systems follow:

Ubuntu

Helper script

  • run_sundials/ubuntu_buildrun.sh

# BASH
#   Run commands from the root CDS directory

# View script help text for details and examples
./run_sundials/ubuntu_buildrun.sh -h

# To build and execute the pendulum example
chmod +x "./run_sundials/ubuntu_buildrun.sh"
./run_sundials/ubuntu_buildrun.sh -cbe -r myResults -t myModels-myPendulum

The solution will be created at data/sundials_results/myResults/myModels-myPendulum.txt

Windows (Visual Studio via CLI)

Helper scripts

  • run_sundials/clearBuild.ps1
  • run_sundials/rebuild.ps1
  • run_sundials/runExe.ps1

# PowerShell
#   Run commands from the root CDS directory

# View script help text for details and examples
Get-Help run_sundials/clearBuild.ps1
Get-Help run_sundials/rebuild.ps1
Get-Help run_sundials/runExe.ps1

# To build and execute the pendulum example
# NOTE: It may be necessary to edit rebuild.ps1 to match the path to the compiler to your version of Visual Studio
./run_sundials/rebuild.ps1
./run_sundials/runExe.ps1 "myModels-myPendulum" > "./data/sundials_results/myResults/myModels-myPendulum.txt"

The solution will be created at data/sundials_results/myResults/myModels-myPendulum.txt

Windows (Visual Studio via GUI)

  1. Open the CMake project from within Visual Studio:
    1. File > Open > CMake...
    2. Choose run_sundials\src\CMakeLists.txt
  2. Generate the CMake cache: CMake > Cache > Generate
  3. Build: CMake > Build Only > ...

After building, the executable must be run with PowerShell. 


# PowerShell
#   Run commands from the root CDS directory

# To build and execute the pendulum example
./run_sundials/runExe.ps1 "myModels-myPendulum" > "./data/sundials_results/myResults/myModels-myPendulum.txt"

The solution will be created at data/sundials_results/myResults/myModels-myPendulum.txt

To edit the build settings, open run_sundials\src\CMakeSettings.json from within Visual Studio, while the project is open.

It may be necessary to delete the CMake cache between builds.

Step 4: Load the Solution into MATLAB

The solution data should be loaded directly into MATLAB, and then passed to CDS_Solution, just as it would if it had been output by calling CDS_Solver.Solve normally. Before importing the solution, you are required to recreate an identical copy of the CDS_SystemDescription that generated the exported solution. It is assumed that this is exactly identical, and this assumption is not automatically verified. To do this, it is suggested to simply reuse the same MATLAB script that generated the C++ output, but with the .Solve command commented out and replaced with a readmatrix command.

Additionally, the command .params.SetStateVectorMode("withoutLambda") should be run to specify that the SUNDIALS solution does not include the lagrange multipliers in the state vector or solution data. This command should always be called when using a SUNDIALS solution.

% Given:
%   The solution is in "data/sundials_results/myResults/myModels-myPendulum.txt"
%   sys = CDS_SystemDescription

% Read in the txt/csv results
importPath = CDS_GetDataLocations().sun_results("myResults", "myModels-myPendulum.txt");
dataRaw = readmatrix(importPath);
t_import = dataRaw(:, 1).';
x_import = dataRaw(:, 2:end).';

% Remove the solver stats
t = t_import(isfinite(t_import));
x = x_import(:, isfinite(t_import));

% Build the solution object
sys.params.SetStateVectorMode("withoutLambda");
SS = CDS_SolutionSim(sys, t, x);

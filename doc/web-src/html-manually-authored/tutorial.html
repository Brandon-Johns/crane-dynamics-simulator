Tutorial: Create and Run Your First Model

This tutorial is recommended as an introduction to all users.

You will learn how to use this package to simulate a triple pendulum.

Steps:

  1. Define the model on paper
  2. Create a new run-file
  3. Define the model in code
  4. Run the solver
  5. Post-process the solution

The full code of this example is run_matlab/Examples/E8_TriplePendulum.m

Define the Model on paper

To define your model:

  • Draw the kinematic chain
  • Assign constant parameters (e.g. gravity, link lengths)
  • Assign generalised coordinates (e.g. joint angles, lengths of prismatic joints)
  • Assign a coordinate frame to every joint and centre of mass location
  • Attach mass and/or moment of inertia to the coordinate frames

There is no need to write equations. A labelled diagram is sufficient.

{{--Rendered from "doc/web-src/svg/TriplePendulum-js.html"--}}

For the triple pendulum, I have used

  • Constants
    • {{@matlab}}g = 9.8{{/matlab}}, magnitude of gravitational acceleration
    • {{@matlab}}L_1 = 1{{/matlab}}, link length from {{@matlab}}O{{/matlab}} to {{@matlab}}A{{/matlab}}
    • {{@matlab}}L_2 = 1{{/matlab}}, link length from {{@matlab}}A{{/matlab}} to {{@matlab}}B{{/matlab}}
    • {{@matlab}}L_3 = 1{{/matlab}}, link length from {{@matlab}}B{{/matlab}} to {{@matlab}}C{{/matlab}}
  • Generalised coordinates
    • {{@matlab}}theta_1{{/matlab}}, with initial conditions \theta_1 = \pi/4 and \dot{\theta}_1 = 0
    • {{@matlab}}theta_2{{/matlab}}, with initial conditions \theta_2 = 0 and \dot{\theta}_2 = 0
    • {{@matlab}}theta_3{{/matlab}}, with initial conditions \theta_3 = 0 and \dot{\theta}_3 = 0
  • Frames
    • {{@matlab}}O{{/matlab}}: World frame at top of pendulum
    • {{@matlab}}O2{{/matlab}}: First joint
    • {{@matlab}}A{{/matlab}}: Second Joint
    • {{@matlab}}B{{/matlab}}: Third Joint
    • {{@matlab}}C{{/matlab}}: End of final link
  • Mass and moment of inertia
    • At {{@matlab}}A{{/matlab}}: m_A = 1 and I_A = 0_{3,3}
    • At {{@matlab}}B{{/matlab}}: m_B = 1 and I_B = 0_{3,3}
    • At {{@matlab}}C{{/matlab}}: m_C = 1 and I_C = 0_{3,3}

Create a new run-file

Initial Setup

  • Download this repository
  • Create a new directory within run_matlab
    • e.g. run_matlab/MyProject
  • Copy in a CDS_FindIncludes.m file from one of the other folders within run_matlab
  • Edit this file so that it adds core/includes_matlab/ to the MATLAB path

Create a run-file

  • In the new directory, create a new matlab script (I call this a run-file, because it runs the simulator)
    • e.g. run_matlab/MyProject/TriplePendulum.m
  • At the top of the run-file, add the code
{{@matlab-pre}} CDS_FindIncludes; CDS_IncludeSimulator; {{/matlab-pre}}

You should now have created

  • run_matlab/MyProject/CDS_FindIncludes.m
  • run_matlab/MyProject/TriplePendulum.m

Define the Model in code

Continuing editing the run-file, incrementally adding in the code snippets that follow

System Description

The {{@matlab}}CDS_SystemDescription{{/matlab}} object holds and manages the information required to simulate a given system.

Exactly one of these should be created for each system being defined.

{{@matlab-pre}} % System description % This contains all of the information required to simulate the system sys = CDS_SystemDescription(); {{/matlab-pre}}

This is a handle object, it is passed by reference. It is not possible to clone this object because it internally contains and manages references to the many objects the collectively define the system.

The {{@matlab}}CDS_SystemDescription{{/matlab}} is a builder and manager type object. Its methods are called to build the components of the system, and it holds a reference to each object that it builds. Thus, it is also used to retrieve information about the system.

Parameters

Each {{@matlab}}CDS_SystemDescription{{/matlab}} holds a single instance of {{@matlab}}CDS_Params{{/matlab}}, which is a builder / manager object for system parameters:

  • Constants
  • Free variables (generalised coordinates)
  • Driven variables (system inputs)

All parameters must be created with this single {{@matlab}}CDS_Params{{/matlab}} instance by calling {{@matlab}}.Create(){{/matlab}}.

Appropriate {{@matlab}}.Set{{/matlab}} methods can optionally be chained to the output.

{{@matlab-pre}} % Builder/manager object params = sys.params; % System parameters % Define and set the numeric value params.Create('const', 'L_1').SetNum(1); params.Create('const', 'L_2').SetNum(1); params.Create('const', 'L_3').SetNum(1); params.Create('const', 'g').SetNum(9.8); % Generalised coordinates % Define and set the initial conditions params.Create('free', 'theta_1').SetIC(pi/4); params.Create('free', 'theta_2').SetIC(0); params.Create('free', 'theta_3').SetIC(0); {{/matlab-pre}}

Aside: This syntax is known as method chaining, and it can be understood as the combination of

{{@matlab-pre}} tmp = params.Create('const', 'myVar'); tmp.SetNum(1); {{/matlab-pre}}

Note that {{@matlab}}CDS_Params.Create('myType', 'myVar'){{/matlab}} has the side effect of calling {{@matlab}}syms myVar{{/matlab}} in the current workspace.

Points / Kinematic Chains

The geometry of the system can now be described, in terms of the parameters, as a set of homogeneous transformation matrices

{{@matlab-pre}} % Forward kinematics between the frames % NOTE: Using shorthand notation. See the aside for explanation T_OO2 = CDS_T('atP', 'z', theta_1-sym(pi)/2, [0;0;0]); T_O2A = CDS_T('atP', 'z', theta_2, [L_1;0;0]); T_AB = CDS_T('atP', 'z', theta_3, [L_2;0;0]); T_BC = CDS_T('atP', 'z', 0, [L_3;0;0]); % Combine to obtain the transformation to each frame as relative to the base frame T_OA = T_OO2 * T_O2A; T_OB = T_OA * T_AB; T_OC = T_OB * T_BC; {{/matlab-pre}}

The notation {{@matlab}}T_AB{{/matlab}} means the transformation matrix that satisfies the relation {{@matlab}}P_A = T_AB * P_B{{/matlab}} where {{@matlab}}P_A{{/matlab}} is a point as measured in frame A, and {{@matlab}}P_B{{/matlab}} is the same point as measured in frame B.

Aside: {{@matlab}}CDS_T(){{/matlab}} accepts shorthand inputs as well as full 4x4 transformation matrices

{{@matlab-pre}} % These are equivalent ('P' means point) CDS_T('P', [x;y;z]); CDS_T([1,0,0,x; 0,1,0,y; 0,0,1,z; 0,0,0,1]); % These are equivalent ('at' means rotation about the x, y, or z axis by theta) CDS_T('at', 'z' theta); % Rotation about the z axis CDS_T([1,0,0,0; 0,cos(theta),-sin(theta),0; 0,sin(theta),cos(theta),0; 0,0,0,1]); % These are equivalent (Combination of the above) CDS_T('atP', 'z', theta, [x;y;z]); CDS_T([1,0,0,x; 0,cos(theta),-sin(theta),y; 0,sin(theta),cos(theta),z; 0,0,0,1]); {{/matlab-pre}}

Next, all particles and rigid bodies must be created with the {{@matlab}}CDS_SystemDescription{{/matlab}} by calling {{@matlab}}.CreatePoint().SetT_0n(){{/matlab}}

  • Notation
    • '0' means the base frame (world frame)
    • 'n' means the frame of the current point
  • Points are locations defined by a transformation matrix (they have both position and orientation)
    • Particles are points that have mass
    • Rigid bodies are points that have mass and moment of inertia
  • Uses
    • Only particles and rigid bodies influence the solution dynamics
    • Other points may be optionally defined by omitting the mass and moment of inertia inputs
    • The locations of all points are calculated after solving, so that their values may be queried or plotted
{{@matlab-pre}} % SYNTAX: .CreatePoint('Name', mass, inertia) O = sys.CreatePoint('O'); A = sys.CreatePoint('A', 1).SetT_0n(T_OA); B = sys.CreatePoint('B', 1).SetT_0n(T_OB); C = sys.CreatePoint('C', 1).SetT_0n(T_OC); {{/matlab-pre}}

The structure of the kinematic chain is then declared as a set of arrays.

  • This has no effect on the physics of the problem; it does not effect the solution
  • It is only used for plotting the animation
  • The plotter will draw animated lines joining the points in each array
{{@matlab-pre}} % Kinematic chains (used only for plotting the animation) sys.SetChains([O,A,B,C]); {{/matlab-pre}}

Gravity

The magnitude and direction of gravity should be defined as an acceleration vector, as measured in the base frame.

In this case, I have chosen y as up in the base frame, with gravity pointing in the negative y direction.

{{@matlab-pre}} % Direction of gravity in base frame sys.SetGravity([0; -g; 0]); {{/matlab-pre}}

This completes description of our triple pendulum system.

Run the Solver

Now that the system has been completely defined, the package can automatically generate and solve the equations of motion

The final options to choose are:

  • The time to solve over
    • Specified either as a range, or a set of values to evaluate
    • This does not influence the values that the solver uses internally, only the values that are output
  • The integration tolerances
  • The solver
    • {{@matlab}}.Solve(sys){{/matlab}} (Automatic)
    • {{@matlab}}.Solve(sys, "ode89"){{/matlab}} Specify a MATLAB ODE solver
    • {{@matlab}}.Solve(sys, "drawIC"){{/matlab}} Skip solving and just plot the initial conditions
    • {{@matlab}}.Solve(sys, "sundials"){{/matlab}} Export the equations to C++ for solving with SUNDIALS
  • The equation formulation method
    • For almost all cases, the best option is to use the automatic mode
{{@matlab-pre}} SO = CDS_Solver_Options(); SO.time = 0 : 0.02 : 20; SO.RelTol = 1e-10; SO.AbsTol = 1e-10; % Generate and solve equation of motion S = CDS_Solver(SO); [t,x,xd] = S.Solve(sys); {{/matlab-pre}}

This results in the solution to the differential equation, in the traditional form that is output by an ODE solver

  • {{@matlab}}t{{/matlab}} The time that the solution is sampled at
  • {{@matlab}}x{{/matlab}} The values of the state vector at these times
  • {{@matlab}}xd{{/matlab}} The values of the state vector derivative at these times

Where the automatically generated state vector can be viewed with

{{@matlab-console-pre}} >> sys.params.x.Sym ans = theta_1d theta_2d theta_3d theta_1 theta_2 theta_3 {{/matlab-console-pre}}

The variables

  • {{@matlab}}theta_1{{/matlab}}, {{@matlab}}theta_2{{/matlab}}, and {{@matlab}}theta_3{{/matlab}} are as we defined.
    • Recall that each parameter was named during its creation; when {{@matlab}}sys.params.Create(){{/matlab}} was called
  • with the suffix {{@matlab}}d{{/matlab}} are their time derivatives (velocity), as have been automatically created.
  • with the suffix {{@matlab}}dd{{/matlab}} are their double time derivatives (acceleration), as have been automatically created.

Given that we requested the solution time as {{@matlab}}SO.time = 0 : 0.02 : 20;{{/matlab}}, then the sizes of the solution arrays are

  • {{@matlab}}t(1,1001) double{{/matlab}}
  • {{@matlab}}x(6,1001) double{{/matlab}}
  • {{@matlab}}xd(6,1001) double{{/matlab}}

Thus, you can now use the solution however you usually would, having it in the traditional form that is output by an ODE solver.

Or you can use the provided tools to automate performing various calculations and creating plots of the solution.

Post-Process the Solution

The {{@matlab}}CDS_SystemDescription{{/matlab}} holds the description of the system, in the terms that we defined it.

This is a perfect match for automating the creation of plots in terms of these same variables.

In post-processing, the {{@matlab}}CDS_SystemDescription{{/matlab}} is used to generate equations, and the solution {{@matlab}}t, x, xd{{/matlab}} is fed into these equations.

We can

  • Query the values of generalised coordinates by name
  • Calculate and query the position of each point by name
  • Calculate and query the energies of each particle / rigid body by name
  • Generate plots
  • Generate a real-time animation of the motion
{{@matlab-pre}} SS = CDS_SolutionSim(sys, t,x,xd); SSp = CDS_Solution_Plot(SS); SSa = CDS_Solution_Animate(SS); SSp.PlotConfigSpace SSp.PlotLambda SSp.PlotInput SSp.PlotEnergyTotal SSp.PlotEnergyAll SSp.PlotTaskSpace SSa.Set_View_Predefined("front") SSa.PlotFrame SSa.Animate("play") % Click the "Repeat" button on the figure to play the animation! %SSa.Animate("gif") %SSa.Animate("video") {{/matlab-pre}}

The post-processed data can be exported to excel in a human readable format

{{@matlab-pre}} % Export SSe = CDS_Solution_Export(SS); SSe.DataToExcel("mySolution.xlsx"); {{/matlab-pre}}

The post-processed data can also be queried by using the names of the parameters / points

  • Recall that each parameter / point was named during its creation; when {{@matlab}}sys.params.Create(){{/matlab}} or {{@matlab}}sys.CreatePoint(){{/matlab}} was called
{{@matlab-pre}} SSg = CDS_Solution_GetData(SS); % Get the value of theta_2, and its derivatives at the time 3.8 seconds idx = SS.t_idx(3.8); fprintf("theta_2 at 3.8s = %g\n", SSg.q("theta_2", idx)); fprintf("d[theta_2]/dt at 3.8s = %g\n", SSg.qd("theta_2", idx)); fprintf("d^2[theta_2]/dt^2 at 3.8s = %g\n", SSg.qdd("theta_2", idx)); % Get the x,y,z locations of point C at this same time fprintf("x coordinate of point C at 3.8s = %g\n", SSg.Px("C", idx)); fprintf("y coordinate of point C at 3.8s = %g\n", SSg.Py("C", idx)); fprintf("z coordinate of point C at 3.8s = %g\n", SSg.Pz("C", idx)); {{/matlab-pre}}

Add a Constraint

Using {{@matlab}}sys.CreateConstraint("name").SetConstraint(C){{/matlab}} specifies that the solution must satisfy the algebraic equation C=0.

Try different constraints by adding the following to the system description, before calling solve

{{@matlab-pre}} % This constraint can fix the linkage to slide along a rail % Enable only one at a time! %sys.CreateConstraint("Bx").SetConstraint(T_OB.x, "offsetToIC"); sys.CreateConstraint("By").SetConstraint(T_OB.y, "offsetToIC"); %sys.CreateConstraint("Cx").SetConstraint(T_OC.x, "offsetToIC"); %sys.CreateConstraint("Cy").SetConstraint(T_OC.y, "offsetToIC"); sys.SetConstraint_StabilisationFactors(); {{/matlab-pre}}

The option {{@matlab}}"offsetToIC"{{/matlab}} modifies the input constraint equation to enforce C=0. The value of the provided constraint equation (in terms of the system parameters) is calculated at the initial conditions, and then the equation is offset by this value, such that it equals 0 in initial condition. Otherwise, the constraint equation would be inconsistent with the initial conditions, and the system would be unsolvable.

Internally, this uses the helpful function {{@matlab}}.params.EvaluateSymExpr_IC(){{/matlab}}

{{@matlab-console-pre}} % This does not equal 0 in the initial conditions >> T_OB.y ans = - L_2*(cos(theta_1)*cos(theta_2) - sin(theta_1)*sin(theta_2)) - L_1*cos(theta_1) % This is equal to 0 in the initial conditions >> T_OB.y - sys.params.EvaluateSymExpr_IC(T_OB.y) ans = 2^(1/2) - L_2*(cos(theta_1)*cos(theta_2) - sin(theta_1)*sin(theta_2)) - L_1*cos(theta_1) {{/matlab-console-pre}}

The function {{@matlab}}.SetConstraint_StabilisationFactors(){{/matlab}} makes the solver use 'Baumgarte stabilisation'. It makes a trade off to reduce numerical error, at the expense of making the differential equations stiff (more difficult to solve). It is optional to use, and the strength can be tuned.

Add Explicit Time Dependence

The symbolic variable to represent time is always {{@matlab}}sym('t','real'){{/matlab}}. There is no need to create a parameter for it; the sym is automatically recognised by the software. To use this sym, you should instance as per the usual with the symbolic toolbox

{{@matlab-pre}} syms t real {{/matlab-pre}}

Let us make the top of the pendulum move according to the trajectory L_O(t) = sin(t). You can imagine that the top of the pendulum is being driven by an externally controlled servomotor. This means that the total system energy will not necessarily be conserved. There are multiple ways to implement this, as follows

It may be necessary to first remove any previously added constraints as to not cause impossible geometry!

Method 1: Explicitly time dependent Lagrangian

Implement the following changes to make the Lagrangian explicitly time dependent

{{@matlab-pre}} % Change this T_OO2 = CDS_T('atP', 'z', theta_1-sym(pi)/2, [sin(sym('t','real'));0;0]); % Change this O = sys.CreatePoint('O').SetT_0n(T_OO2); {{/matlab-pre}}

Method 2: Rheonomic constraints

Implement the following changes to make the constraint equations explicitly time dependent (rheonomic)

{{@matlab-pre}} % Add this params.Create('free', 'L_O'); constraint = L_O - sin(sym('t','real')); sys.CreateConstraint("top").SetConstraint(constraint, "offsetToIC"); sys.SetConstraint_StabilisationFactors(100); % Change this T_OO2 = CDS_T('atP', 'z', theta_1-sym(pi)/2, [L_O;0;0]); % Change this O = sys.CreatePoint('O').SetT_0n(T_OO2); {{/matlab-pre}}

Method 3: Inputs

Inputs are parameters that vary with time according to a predefined function. Note that using inputs indirectly makes the Lagrangian time dependent.

Implement the following changes to specify an input

{{@matlab-pre}} % Add this params.Create('input', 'L_O').SetAnalytic(sin(sym('t','real'))); % Change this T_OO2 = CDS_T('atP', 'z', theta_1-sym(pi)/2, [L_O;0;0]); % Change this O = sys.CreatePoint('O').SetT_0n(T_OO2); {{/matlab-pre}}

A key use for inputs instead of explicit time dependence is for to specify a piecewise function of time, or a data-driven trajectory (e.g. cubic spline fit to sampled data points)

Add Springs, Dampers, and Forces

Springs and dampers can have their lengths specified by arbitrary expressions, using the {{@matlab}}.SetLength(){{/matlab}} method. Alternatively, the length can be indirectly specified by the {{@matlab}}.SetConnections(){{/matlab}} method, which defines the length by the locations where it starts and ends.

A point force is specified by the location where it acts, and the value of the force. A generalised force is specified by the generalised coordinate upon which it acts, and the value of the force.

Implement the following changes to add in these components

{{@matlab-pre}} % Add any combination of these sys.CreateLinearSpring("AC").SetSpringConstant(7).SetConnections(A,C); sys.CreateLinearDamper("OC").SetDampingConstant(2).SetConnections(O,C); sys.CreatePointForce("Cx").SetLocation(C).SetF([10,30,0]); sys.CreateGeneralisedForce("B").SetLocation(theta_2).SetQ(8); {{/matlab-pre}}
